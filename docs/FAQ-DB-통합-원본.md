# FAQ DB 통합 원본 초안

> 역할: 승인 후 DB 초기 데이터로 변환할 FAQ 제목·내용의 통합 작업 원본. 작성 규칙은 `FAQ-자료-정리와-DB-구축-기준.md`를 따르며 카테고리별 문서는 추출 범위 참고용이다.

> 용도: 승인된 FAQ 본문을 나중에 SQL 초기 데이터로 변환할 때 사용할 기준 원본.
> 상태: FAQ 후보 39건 모두 초안. 사용자 확인이 필요한 쟁점은 확정 FAQ 데이터에서 제외.
> 대상: `yangwiki`의 양품화 매뉴얼 사이트 본문. FAQ 내용은 사이트 본문 기준으로 정리.

## 작성 및 DB 변환 기준

- FAQ 본문은 `title`과 `content`로 구성. 질문형 제목이나 답변체 문장 불필요.
- `title`은 검색할 업무 주제를 간결하게 표시. `content`는 명사형·항목형 표현 우선.
- 같은 기준의 여러 사례는 공통 내용으로 압축. 기기·OS·사업·시기에 따라 적용 결과가 다르면 조건을 보존해 분리.
- `category`, `topic`, `keywords`, `status`, `review_note`는 초안 검토용 정보. SQL 운영 데이터에는 FAQ 업무 필드와 키워드만 옮기며 `status`, `review_note`는 제외.
- 숫자 자동 증가 `id`와 `created_at`은 DB가 생성. 이 원본에서 수동 입력하지 않음.
- `초안`: 사이트 본문을 기준으로 항목을 구성했으며 사용자 최종 확인·승인은 미완료.
- 사용자 확인이 필요한 충돌·정책 결정 사항은 FAQ 후보에 추정 내용으로 기록하지 않는다. 사용자에게 직접 확인한 뒤 합의된 내용만 반영.
- 연도별·학교별·OS별로 달라지는 금액·절차·업체·일정은 적용 조건을 제목 또는 내용에 함께 기재.

## SQL 데이터 변환 전 확인

- `초안`도 사용자 승인 전에는 초기 데이터 SQL에 넣지 않는다.
- `검토 필요`는 적용 범위·최신성 확인과 사용자 승인 전 초기 데이터에서 제외한다.
- 승인된 FAQ만 `title`, `content`, `category`, `topic`, `keywords`로 변환한다. 숫자 `id`와 `created_at`은 DB 자동 생성.
- 사용자 승인 상태와 검토 메모는 이 문서에만 보존하고 운영 테이블에 넣지 않는다.
- 본문·분류·키워드 수정은 이 통합 원본에 우선 반영한다. 카테고리별 문서의 기존 요약 표는 SQL 이관 원본으로 사용하지 않는다.
