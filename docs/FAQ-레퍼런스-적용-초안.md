# 레퍼런스 FAQ 적용 작업 초안

> 역할: 사용자가 제공한 FAQ 레퍼런스를 기존 FAQ 원본과 대조하기 위한 작업 초안. 이 문서는 검토용이며 SQL/운영 DB에 바로 반영하지 않는다.

## 작업 기준

- 기존 38건은 기존 FAQ ID를 유지하면서 제목·내용·topic을 갱신하는 방향.
- 첨부 자료의 질문을 기존 항목과 비교해 갱신, 신규, 통합, 제외 후보로 분류.
- 실제 답변은 핵심 안내 → 적용 조건·절차 → 예외·후속 조치 순으로 작성.
- 첨부 자료의 '미해결 대책 및 내용 설명'은 그대로 답변에 넣지 않는다. 안내에 필요한 확정 내용만 추리고, 내부 전달 사항·개인 연락 정보는 운영 FAQ에서 제외.
- 연도별 요율·단가·업체·경로는 해당 연도를 함께 적고, 현재 기준 확인 전에는 확정 답변으로 쓰지 않는다.
- 사용자 확인 전의 내용은 SQL로 만들지 않는다.

## 첨부 자료 규모

- 문의 내용이 있는 원시 행: 331건
- 문의 내용이 비어 있는 행: 18건
- 원시 행 331건은 FAQ 확정 건수가 아니다. 중복·통합·구정보·내부용·프로젝트 범위 밖 항목을 대조한 뒤 실제 신규 수를 확정한다.

## 확정 Topic 체계

`topic`은 별도 테이블이 아닌 `faqs.topic` 문자열 값이다. 따라서 스키마 변경 없이 새 값을 사용할 수 있지만, 기존 명칭과 중복되지 않도록 아래 업무 주제에서 선택해 일관되게 사용한다.

| 대분류 | Topic 후보 |
|---|---|
| 2027년 양품화 사업 | 사업 일반, 수거 일정, 수거 대상, 지급 품목, 학교 사전준비(OS별), 기타 문의, 관리전환·재배부, 디벗관리시스템, 스마트단말관리시스템 |
| 유지보수 | 시스템·관리, 일반·운영, A/S 및 구매, Chrome, Android, IOS, Windows, Whale |
| 2027년 디벗 재배치·여분기기 수거 사업 | 사업 일반 |

`Chrome`은 Chromebook 관련 안내를 의미한다. 세부 시스템 안내와 업무 내용의 분류는 사용자 확정 기준을 따르며, 기존 FAQ의 ID·제목·내용은 Topic 통합 과정에서 변경하지 않는다.

## 1차 대조 요약

- A/S·구매 원시 문의 35건 가운데 기존 FAQ의 A/S 접수·비용·펜슬·구매·단체 접수 항목과 겹치는 갱신 후보가 다수다.
- 제안상 기존 FAQ 갱신 연결: 12건. 신규 후보: 22건. 사용자 확인 또는 최신성 확인이 필요한 항목: 20건. 이 수치는 행 단위의 임시 분류이며, 확인 항목은 갱신·신규 후보와 중복 집계될 수 있다.
- 기존 FAQ에서 이 묶음과 직접 대응하지 않는 나머지 항목도 이 자료 전체 대조에서 별도로 갱신 여부를 판단한다.
- 다음에는 2027년 양품화·여분기기 사업 문의와 일반 디벗·시스템·OS 문의를 같은 방식으로 분류하고, 전체 중복 제거 후 최종 신규 건수를 산정한다.

## 사용자 확인이 필요한 사항

1. 취약계층·화재 지원은 2022·2024·2025 도입 기기별 요율과 지원 횟수가 기록되어 있다. 현재 운영 중인 연도별 기준을 알려주면 그 범위만 FAQ에 반영한다.
2. 2026년 9월 1일 이전 애플펜슬 구성·교체 안내, 호환 캡 선정 대기, 보호·펜슬 케이스 재고 메모는 현재도 유효한지 확인이 필요하다.
3. 2027년 양품화에서 받은 기존 기준과 첨부 유지보수 자료의 반납 품목 안내가 다를 경우, FAQ는 각 사업·기기 보급 연도를 분리해 안내하는 것으로 진행한다.

## SQL 반영 전환안

- Topic 통합은 `V6__normalize_faq_topics.sql` 신규 Flyway 마이그레이션으로 수행한다. 이미 작성된 V1~V5는 수정하지 않는다.
- 기존 38건은 확인된 ID를 유지하며 `topic`, `title`, `content`를 갱신한다. 기존 키워드는 새 문의 표현에 맞춰 교체하고 FAQ 열람 집계는 유지한다.
- 신규 FAQ는 자동 ID로 추가하고 키워드·열람 집계 행을 함께 만든다.
- 검토 중 항목은 운영 데이터에 넣지 않는다. 실제 DB 반영 전 백업·대상 행 수 확인 절차를 둔다.
